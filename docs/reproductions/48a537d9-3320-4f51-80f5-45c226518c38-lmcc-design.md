## Evidence Plan

Create `submissions/rethinking-code-complexity-through-the-lens-of-large-language-models/` with an independently executable Python package and a small static Space UI. The evidence command clones the pinned upstream repository into `/tmp`, records commit and file hashes, and reads only released public artifacts.

The implementation will avoid installing the upstream package because its requirements include heavyweight LLM serving dependencies. Instead it will reimplement the small, auditable computations needed for the selected claims:

- For the metric-construction claim, parse upstream `scripts/lm_cc/lm_cc.py` and verify the released formula uses `total_branch = block_count - 1`, `depth_sum`, and `LMCC = depth_sum * (1 - 0.8) + total_branch * 0.8`. Also compute LM-CC on synthetic block trees to show depth and branching contributions.
- For the correlation claim, load upstream cached `block_trees-*`, `loc.json` if present or recompute LOC from cached block-tree code, and result JSON files for program repair, code translation, and execution reasoning. Recompute grouped partial Spearman correlations with the same grouping search described by the upstream utility, without copying table values.
- For the rewrite claim, compare original versus `*-simplified` released result JSON files and matching cached block trees where available. Report recomputed pass@1 deltas and LM-CC median reductions for the released simplified subsets. Mark the claim `toy` if the released subset does not fully support the headline 20.9% maximum.

The evidence bundle will be `evidence/bundle.json` and include command line, Python version, upstream URL, upstream commit, source file hashes, selected claim bindings, observations, statuses, and unreplicated claims.
